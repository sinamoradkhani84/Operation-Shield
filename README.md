# Operation-Shield

 پروژه‌ای با هدف بهبود دسترسی‌پذیری و پایداری لینک‌های اشتراک طراحی شده است. این پروژه تلاش می‌کند محدودیت‌های اعمال‌شده روی ساب‌دامین‌ها را که ممکن است مانع Import شدن کانفیگ‌ها و به‌روزرسانی اشتراک‌ها شوند، برطرف کند.

هدف اصلی پروژه این است که کاربران بتوانند لینک اشتراک خود را به‌راحتی وارد کلاینت کنند، کانفیگ‌های خود را به‌روزرسانی کنند و بدون دردسر از سرویس استفاده کنند.

### قابلیت‌های اصلی
- بهبود دسترسی به لینک‌های اشتراک
- رفع مشکلات Import کانفیگ‌ها در کلاینت‌های VPN
- بهبود فرایند به‌روزرسانی و دریافت مجدد اشتراک
- افزایش پایداری دسترسی به لینک‌های Subdomain
- ساده‌سازی تجربهٔ کاربری در مدیریت اشتراک‌ها

**هدف نهایی:** فراهم‌کردن تجربه‌ای پایدارتر، ساده‌تر و قابل‌اعتمادتر برای دریافت و به‌روزرسانی کانفیگ‌های VPN.
## راهنمای پیاده‌سازی در Deno

در این بخش نحوهٔ راه‌اندازی Operation-Shield با استفاده از Deno توضیح داده می‌شود.

### پیش‌نیازها
- نصب Deno یا دسترسی به محیط Deno Deploy
- دسترسی به یک سرور بالادستی معتبر
- آشنایی مقدماتی با متغیرهای محیطی و درخواست‌های HTTP

### مراحل راه‌اندازی

**۱. دریافت پروژه**

مخزن پروژه را از GitHub دریافت کنید:

```bash
git clone https://github.com/USERNAME/Operation-Shield.git
cd Operation-Shield
```

به‌جای `USERNAME` نام کاربری GitHub مالک مخزن را وارد کنید.

**۲. تنظیم متغیرهای محیطی**

متغیرهای موردنیاز پروژه را در محیط اجرا تعریف کنید. اطلاعات مربوط به سرور بالادستی باید در تنظیمات محیطی نگهداری شوند و نباید در مخزن عمومی قرار بگیرند.

**۳. اجرای پروژه**

پس از تنظیم متغیرها و بررسی کد، برنامه را با Deno اجرا کنید:

```bash
deno run --allow-net --allow-env main.ts
```

**۴. استقرار در محیط میزبانی**

برای اجرای دائمی، پروژه را در محیط میزبانی سازگار با Deno مستقر کنید و متغیرهای محیطی موردنیاز را از بخش تنظیمات همان سرویس وارد کنید.

**۵. آزمایش عملکرد**

پس از استقرار، مسیر اصلی سرویس و مسیرهای تعریف‌شده برای اشتراک را بررسی کنید. وضعیت پاسخ‌های HTTP، خطاهای ارتباطی و رفتار کلاینت هنگام دریافت و به‌روزرسانی اشتراک باید آزمایش شوند.

### نکات امنیتی
- اطلاعات خصوصی و شناسه‌های واقعی مشتریان را منتشر نکنید.
- دسترسی به مسیرهای اشتراک را متناسب با طراحی سرویس کنترل کنید.
- از ثبت اطلاعات حساس در لاگ‌ها خودداری کنید.
- پیش از استفادهٔ عملیاتی، مدیریت خطا و محدودیت درخواست‌ها را بررسی کنید.
