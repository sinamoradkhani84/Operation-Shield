# Operation-Shield

 پروژه‌ای با هدف بهبود دسترسی‌پذیری و پایداری لینک‌های اشتراک طراحی شده است. این پروژه تلاش می‌کند محدودیت‌های اعمال‌شده روی ساب‌دامین‌ها را که ممکن است مانع Import شدن کانفیگ‌ها و به‌روزرسانی اشتراک‌ها شوند، برطرف کند.

هدف اصلی پروژه این است که کاربران بتوانند لینک اشتراک خود را به‌راحتی وارد کلاینت کنند، کانفیگ‌های خود را به‌روزرسانی کنند و بدون دردسر از سرویس استفاده کنند.

### قابلیت‌های اصلی
- بهبود دسترسی به لینک‌های اشتراک
- رفع مشکلات Import کانفیگ‌ها در کلاینت‌های VPN
- بهبود فرایند به‌روزرسانی و دریافت مجدد اشتراک
- افزایش پایداری دسترسی به لینک‌های Subdomain
- ساده‌سازی تجربهٔ کاربری در مدیریت اشتراک‌ها

**هدف نهایی:** فراهم‌کردن تجربه‌ای پایدارتر، ساده‌تر و قابل‌اعتمادتر برای دریافت و به‌روزرسانی کانفیگ‌های VPN.

## راهنمای پیاده‌سازی در Deno Deploy

در این بخش، مراحل راه‌اندازی **Operation-Shield** با استفاده از سرویس Deno Deploy توضیح داده می‌شود.

### ۱. ساخت حساب کاربری

ابتدا از طریق لینک زیر وارد وب‌سایت Deno Deploy شوید و یک حساب کاربری ایجاد کنید:

🔗 https://deno.com/deploy

پیش از شروع، محدودیت‌های پلن رایگان و شرایط استفاده از آن را بررسی کنید؛ سهمیهٔ درخواست‌ها و شرایط ثبت‌نام ممکن است تغییر کند.

### ۲. ایجاد یک پروژه

پس از ورود به حساب کاربری:

1. به بخش **App** بروید.
2. روی فلش کنار گزینهٔ **New Playground** کلیک کنید.
3. گزینهٔ **Hello World Template** را انتخاب کنید.

### ۳. وارد کردن کد پروژه

فایل `sub.ts` را از مخزن [Operation-Shield](https://github.com/sinamoradkhani84/Operation-Shield) باز کنید و کد آن را کپی کرده و در محیط ویرایشگر Deno قرار دهید.

پیش از انتشار پروژه، مقادیر موردنیاز مشخص‌شده در کد را متناسب با تنظیمات خود تغییر دهید. از قرار دادن اطلاعات حساس، توکن‌ها یا شناسه‌های خصوصی کاربران در مخزن عمومی خودداری کنید.

### ۴. انتشار پروژه

پس از اعمال تنظیمات، پروژه را با گزینهٔ **Deploy** منتشر کنید. پس از پایان انتشار، آدرس عمومی پروژه در اختیار شما قرار می‌گیرد.

### ۵. ساخت لینک اشتراک

با استفاده از آدرس عمومی پروژه و مسیر تعریف‌شده در کد، لینک اشتراک را مطابق قالب زیر بسازید:

```text
https://YOUR-PROJECT.deno.dev/sub/USER_ID
```

مقادیر `YOUR-PROJECT` و `USER_ID` نمونه هستند و باید با آدرس پروژه و شناسهٔ معتبر موردنیاز پیاده‌سازی شما جایگزین شوند. مسیر نهایی باید با ساختار مسیریابی تعریف‌شده در فایل `sub.ts` مطابقت داشته باشد.

### ۶. بررسی عملکرد

پس از انتشار، موارد زیر را آزمایش کنید:

- دسترسی به آدرس عمومی پروژه
- دریافت پاسخ صحیح از مسیر اشتراک
- دریافت اطلاعات اشتراک از مبدأ تنظیم‌شده
- به‌روزرسانی لینک اشتراک و دریافت کانفیگ‌ها در کلاینت

**نکته:** عملکرد نهایی به تنظیم صحیح مبدأ، مسیرهای درخواست و ساختار پاسخ بستگی دارد. انتشار موفق پروژه به‌تنهایی تضمین نمی‌کند که تمام کلاینت‌ها بتوانند اشتراک را دریافت یا به‌روزرسانی کنند.
