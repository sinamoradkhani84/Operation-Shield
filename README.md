# Operation-Shield

 پروژه‌ای با هدف بهبود دسترسی‌پذیری و پایداری لینک‌های اشتراک طراحی شده است. این پروژه تلاش می‌کند محدودیت‌های اعمال‌شده روی ساب‌دامین‌ها را که ممکن است مانع Import شدن کانفیگ‌ها و به‌روزرسانی اشتراک‌ها شوند، برطرف کند.

هدف اصلی پروژه این است که کاربران بتوانند لینک اشتراک خود را به‌راحتی وارد کلاینت کنند، کانفیگ‌های خود را به‌روزرسانی کنند و بدون دردسر از سرویس استفاده کنند.

### قابلیت‌های اصلی
- بهبود دسترسی به لینک‌های اشتراک
- رفع مشکلات Import کانفیگ‌ها در کلاینت‌های VPN
- بهبود فرایند به‌روزرسانی و دریافت مجدد اشتراک
- افزایش پایداری دسترسی به لینک‌های Subdomain
- ساده‌سازی تجربهٔ کاربری در مدیریت اشتراک‌ها

**هدف نهایی:** فراهم‌کردن تجربه‌ای پایدارتر، ساده‌تر و قابل‌اعتمادتر برای دریافت و به‌روزرسانی کانفیگ‌های VPN.
## راهنمای پیاده‌سازی در Deno

در این بخش نحوهٔ راه‌اندازی Operation-Shield با استفاده از Deno توضیح داده می‌شود.
## 🛠️ روش استفاده و پیاده‌سازی

روش پیشنهادی Operation-Shield بر پایهٔ دریافت کد از GitHub، ویرایش محلی و استقرار دستی در Deno طراحی شده است.

### مراحل اجرا

**۱. دریافت سورس کد**

فایل‌های پروژه را از مخزن GitHub دریافت کنید:

```bash
git clone https://github.com/sinamoradkhani84/Operation-Shield.git
cd Operation-Shield
```

**۲. ویرایش کد**

فایل اصلی پروژه، مانند `sub.ts` یا `main.ts`، را در سیستم خود باز کنید و تغییرات موردنیاز را اعمال کنید.

**۳. آزمایش محلی (اختیاری)**

در صورت نصب بودن Deno، می‌توانید فایل را در محیط محلی اجرا و عملکرد آن را بررسی کنید:

```bash
deno run --allow-net --allow-env main.ts
```

نام فایل و مجوزهای موردنیاز را متناسب با کد پروژه تنظیم کنید.

**۴. استقرار در Deno**

وارد محیط Deno شوید و یک پروژهٔ جدید ایجاد کنید. کد اصلاح‌شده را در فایل ورودی پروژه قرار دهید، تنظیمات موردنیاز را اعمال کنید و برنامه را مستقر کنید.

**۵. به‌روزرسانی نسخه**

برای دریافت تغییرات جدید، در پوشهٔ پروژه دستور زیر را اجرا کنید:

```bash
git pull origin main
```

پس از دریافت تغییرات، کد را بررسی کنید و در صورت نیاز نسخهٔ جدید را در Deno مستقر کنید.

### 🔐 نکات امنیتی

- اطلاعات حساس سرور و کاربران را در مخزن عمومی منتشر نکنید.
- متغیرهای محیطی و تنظیمات خصوصی را جدا از سورس کد نگه دارید.
- پیش از استقرار نسخهٔ جدید، عملکرد و پاسخ‌های HTTP را بررسی کنید.

### 🎯 هدف روش پیشنهادی

جدا نگه داشتن سورس کد از محیط اجرا، ساده‌سازی ویرایش و آزمایش، نگهداری نسخه‌های مختلف و فراهم کردن امکان استقرار کنترل‌شده در Deno.
